## Что PR #39 реально умеет

1. Изолированная JS state machine `NativePveAuthorityStateLab`, **без импорта в Worker или realtime**, без D1, без сетевых команд.
2. Создание состояния только с маркером `synthetic-pve-test-only`, жёсткой структурой данных и привязкой к owner/pid/room/socket.
3. Серверные тестовые тики `synthetic-server-tick-only`, монотонная ревизия; диапазоны HP/MP, границы карты и время позиции проверяются.
4. Ссылочная проверка ID навыка, ранга и времени cooldown по существующему каталогу original Telegram PPA.
5. Повторные/устаревшие тики, поддельные поля damage, Gold/PPA/loot, чужой владелец и старые сокеты отклоняются.
6. Ни при каком исходе `canAttack`, `canCast` и `canReceiveRewards` не становятся `true`.

## Важное ограничение — **это не готовая серверная игра**

Синтетическая лаборатория НЕ подключена к настоящему общему бою. Реальных авторитетных боевых HP/MP и тиков пока нет. Сохранение Telegram подтверждает профиль/экипировку, но не достоверное текущее HP/MP. Старый realtime в Telegram принимает часть данных от клиента; это нельзя молча считать подтверждением сервера.

До живого PvE остаются:
- Исходный единый server-owned player combat profile на базе валидированных экипировки, рун, уровней, навыков, клановых бонусов.
- Отдельное server-owned хранилище текущих HP/MP, движения, геометрии, buffs/cooldowns для **обоих** клиентов, а не только Godot.
- Проверка коллизий, дальности, честного времени атаки, формул и смерти.
- Общий серверный урон по мобу, строго один kill и атомарная D1 фиксация XP/Gold/PPA/предметов.
- Персистентный durable request/settlement ledger (текущее memory-only replay fencing пригодно лишь для диагностики).
- Изолированное staging Worker+D1, два аккаунта Telegram + Godot и тест на планшете/телефоне.
- После этого — включение флагов, миграция общего Telegram и Godot боевого протокола с защищённым rollout.
